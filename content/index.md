# 논문 작성 가이드

석사·박사 과정에서 함께 읽는 연구와 집필 안내입니다. 주제를 정하는 때부터 원고를 제출할 때까지, 지금 해야 할 일과 원고에 남겨야 할 내용을 순서대로 정리했습니다.

처음 읽는다면 아래 여섯 단계를 따라가세요. 실제 원고가 어떻게 달라지는지 보고 싶다면 [초안에서 제출본까지](case-study.md)를 먼저 읽어도 좋습니다.

## 먼저 이해할 것 {#start}

논문은 **질문을 세우고, 적절한 근거로 답하고, 그 답의 의미와 한계를 설명하는 글**입니다. 기술을 구현했거나 설문을 실시했다는 사실만으로 연구의 기여가 설명되지는 않습니다. 무엇이 밝혀졌으며 기존 연구와 어떻게 연결되는지까지 써야 합니다.

석사와 박사는 이 흐름을 공유합니다. 박사논문을 준비할 때는 개별 결과를 넘어 기존 지식에 무엇을 더했는지, 여러 연구가 하나의 문제에 어떻게 답하는지를 더 깊게 검토하세요. 차이를 장 수·쪽수·설문 표본 수만으로 정하지 않습니다. 연구 범위는 전공과 주제에 맞추고, 실제 자격과 심사 차이는 [학위·제출 요건](requirements.md)에서 확인합니다.

## 01. 관심사를 연구질문으로 좁히기 {#topic}

“AI를 연구하고 싶다”는 관심사입니다. 연구질문은 **대상·상황·문제·확인할 차이 또는 관계**가 드러나야 합니다. 먼저 현장에서 발견한 문제를 적고, 그 문제가 문헌에서도 어떻게 다뤄졌는지 확인합니다.

1. 어떤 대상에게 어떤 문제가 생기는지 구체적으로 적습니다.
2. 지금 쓰는 설명이나 방법이 어디까지 해결하는지 살펴봅니다.
3. 내 연구에서 확인할 질문을 한두 문장으로 좁힙니다.
4. 그 질문에 답할 자료·기간·장비·참여자를 확보할 수 있는지 확인합니다.

예를 들어 “로봇으로 도로 안전을 높인다”는 목적은 넓습니다. “갓길에서 얻는 라이다 정보로 어떤 교통상태를 구분할 수 있는가”처럼 관측 대상과 판별 문제를 정하면, 필요한 자료와 평가 방법을 선택할 수 있습니다. 안전사고 감소까지 주장하려면 그 결과를 직접 확인할 별도의 근거가 필요합니다.

**이 단계에서 남길 것:** 문제, 기존 연구의 한계, 연구질문, 예상 기여, 연구 범위를 담은 짧은 연구개요서. 아직 문헌으로 확인하지 못한 한계는 확인할 질문으로 남깁니다.

**다음으로 가기 전:** 제목에 있는 핵심 단어가 연구질문·자료·평가에 모두 등장하는지 확인하세요. [실제 사례: 연구 범위의 변화](case-study.md#scope)

## 02. 선행연구를 비교하고 내 연구의 자리를 찾기 {#literature}

문헌검토는 읽은 논문을 차례대로 요약하는 작업이 아닙니다. 같은 문제를 다룬 연구를 비교해 **무엇을 알고 있고, 무엇이 충분히 밝혀지지 않았는지** 설명하는 작업입니다. 대학의 문헌검토 안내도 관련 연구의 평가·종합과 연구질문의 연결을 강조합니다. [UNSW 문헌검토 안내](https://www.unsw.edu.au/student/managing-your-studies/academic-skills-support/toolkit/honours-postgraduate/literature-review)

주제의 핵심 개념을 한국어·영어 검색어로 나누고, RISS·Google Scholar·전공 데이터베이스에서 검색합니다. 중요한 논문은 참고문헌과 후속 인용을 따라가며 찾습니다. 검색어·검색일·선정 이유를 간단히 남겨 나중에 빠진 연구를 다시 확인할 수 있게 합니다.

| 비교할 항목 | 읽으면서 적을 내용 |
|---|---|
| 질문과 대상 | 어떤 현상·집단·환경을 연구했는가 |
| 자료와 방법 | 어떤 근거로 답했는가 |
| 결과 | 무엇을 확인했는가 |
| 한계와 내 연구의 관계 | 적용하기 어려운 조건, 남은 질문, 가져올 방법은 무엇인가 |

원고에서는 연구들을 **문제나 비교 기준별로 묶어서** 설명합니다. “A는 무엇을 했고, B는 무엇을 했다”에서 끝내지 말고, 공통점·차이·남은 질문을 연결하세요. “국내 연구가 적다”만으로 연구 필요성을 확정하지 않습니다.

**이 단계에서 남길 것:** 핵심 문헌 비교표와 내 연구가 답할 질문. 인용할 내용은 원문의 해당 쪽·표·그림까지 확인합니다. [실제 사례: 관련연구의 변화](case-study.md#literature)

## 03. 질문에 맞는 자료와 방법 정하기 {#design}

연구설계는 “무엇을 하면 답을 얻을 수 있는가”를 구체화하는 단계입니다. 익숙한 통계 프로그램이나 최신 모델을 먼저 고르기보다, 질문에 필요한 근거부터 정합니다.

| 정할 것 | 확인할 질문 |
|---|---|
| 분석 대상 | 사람, 조직, 문서, 차량, 시간 구간 중 무엇을 하나의 관측으로 볼 것인가 |
| 자료 | 누구에게서, 어느 기간·조건에서, 어떤 자료를 얻을 것인가 |
| 측정·비교 | 개념을 무엇으로 측정하며, 어떤 기준이나 집단과 비교할 것인가 |
| 분석·평가 | 결과를 어떤 방법과 지표로 판단할 것인가 |
| 한계 | 다른 원인, 편향, 누수, 접근 불가능한 자료는 무엇인가 |

사람·조직의 관계를 설명한다면 [설문·관찰 연구](empirical.md), 방법이나 시스템의 차이를 확인한다면 [비교실험](experiment.md)을 참고하세요. 인터뷰·사례연구·혼합연구의 선택 기준은 [연구방법 안내](methods.md)에 있습니다. 모든 연구에 설문·SEM이나 특정 장 구성을 적용하지 않습니다.

자료 수집 전에는 참여자 동의, 개인정보, 자료 이용조건, 필요한 연구윤리 심의 여부를 확인합니다. 예비조사나 작은 실험으로 수집·측정이 가능한지 점검하고, 포함·제외 기준과 분석 계획을 먼저 적습니다.

**이 단계에서 남길 것:** 연구계획서. 문제와 문헌검토에 자료·방법·분석 계획·예상 한계·수행 일정을 붙이면 됩니다. 예상 결과를 이미 얻은 결과처럼 쓰지 않습니다. [실제 사례: 방법 설명의 변화](case-study.md#method)

## 04. 자료를 분석하고 결과를 해석하기 {#analysis}

원자료를 보존한 뒤 정제·제외·변환 과정을 기록합니다. 수집된 자료 수와 실제 분석에 사용한 자료 수가 다르면 그 이유를 설명합니다. 같은 사람이나 같은 실험에서 나온 반복 관측을 서로 독립인 표본처럼 세지 않도록 주의합니다.

결과는 연구질문별로 정리합니다. 각 표와 그림에는 **대상·조건·단위·비교 기준**이 보여야 합니다. 통계 분석은 효과의 크기와 불확실성을, 시스템 실험은 정확도와 함께 필요한 처리시간·자원 조건 등을 보고합니다. 좋은 결과뿐 아니라 실패한 조건과 해석하기 어려운 결과도 설명합니다.

| 결과를 쓸 때 | 점검할 것 |
|---|---|
| “차이가 있었다” | 얼마나 달랐으며 어떤 조건에서 관측했는가 |
| “관계가 있었다” | 인과관계까지 말할 수 있는 설계인가 |
| “유의하지 않았다” | 효과가 없다는 결론과 구분했는가 |
| “성능이 좋아졌다” | 같은 자료·조건에서 비교했고 비용이나 실패 조건도 확인했는가 |

분석 뒤 새로 떠오른 질문은 추가 탐색으로 구분합니다. 결과에 맞춰 처음의 질문이나 제외 기준을 조용히 바꾸지 않습니다. 자료가 부족하면 주장 범위를 줄이거나 필요한 추가 자료를 설명합니다.

**이 단계에서 남길 것:** 핵심 결과표·그림, 각 연구질문에 대한 답, 해석의 한계. 표의 숫자와 본문의 설명을 대조하세요. [실제 사례: 결과 보고의 변화](case-study.md#results)

## 05. 장별 역할을 정하고 초안을 고치기 {#writing}

목차는 연구 내용을 독자가 이해할 순서입니다. 아래 기능을 어디에 배치할지 먼저 정하세요. 연구에 따라 방법과 설계, 결과와 논의를 나누거나 합칠 수 있습니다.

| 논문의 부분 | 독자가 알고 싶은 것 |
|---|---|
| 서론 | 왜 필요한 연구이며 무엇을 묻는가 |
| 관련연구·이론적 배경 | 기존 설명은 어디까지 왔고 내 연구는 어디에 놓이는가 |
| 연구방법·제안방법 | 무엇을 어떻게 했으며 왜 이 방법이 적절한가 |
| 결과 | 어떤 근거를 얻었는가 |
| 논의·결론 | 결과가 무엇을 뜻하며 기여와 한계는 무엇인가 |

처음부터 완벽한 서론을 쓰려 하지 않아도 됩니다. 확보한 자료와 방법, 결과표부터 정리한 뒤 서론의 질문과 결론의 답을 맞추는 방식도 가능합니다. 장 수보다 논리의 연결이 중요합니다. [UNSW 학위논문 구성 안내](https://www.phys.unsw.edu.au/~jw/thesis.html)

초안은 다음 순서로 고칩니다.

1. **논리:** 제목·질문·방법·결과·결론이 같은 연구를 설명하는가.
2. **근거:** 인용이 주장을 뒷받침하고, 수치가 실제 분석과 일치하는가.
3. **구조:** 중복 문단을 합치고 설명이 필요한 위치에 표·그림을 놓았는가.
4. **문장:** 한 문단의 중심 생각이 분명하며 과장·모호한 표현이 없는가.
5. **형식:** 제목, 번호, 인용, 참고문헌과 서식을 일관되게 적용했는가.

초록에는 목적·방법·주요 결과·의미를 담고, 원고가 정리된 뒤 다시 맞춥니다. 국문과 영문 초록의 대상·수치·결론도 같아야 합니다. 인용 스타일은 제출처 기준에 맞춰 하나로 통일합니다. [인용·표·그림 안내](writing.md)

**이 단계에서 남길 것:** 처음부터 끝까지 읽을 수 있는 전체 원고. 문장만 매끄럽게 고친 상태와 근거까지 갖춘 상태는 다릅니다. [실제 사례: 논의와 결론의 변화](case-study.md#discussion)

## 06. 심사 의견을 반영하고 제출본 확인하기 {#defense}

발표에서는 연구 배경을 길게 설명하기보다 **질문 → 방법 → 핵심 결과 → 기여·한계**가 이어지도록 구성합니다. 예상 질문에 답할 때는 해당 표·그림·문헌을 찾을 수 있게 준비합니다. 확인하지 않은 내용은 현재 근거와 추가 검증이 필요한 부분을 구분해 답합니다.

심사 후에는 의견별로 수정 내용을 정리합니다. 의견을 그대로 반영하기 어렵다면 연구 범위와 근거를 들어 설명하고, 필요한 대안 수정을 제시합니다.

| 받은 의견 | 수정한 내용 | 원고 위치 |
|---|---|---|
| 실제 받은 의견을 적습니다 | 바꾼 문장·분석·표와 그 이유를 적습니다 | 장·절·쪽수를 적습니다 |

제출 직전에는 다음을 확인합니다.

- 제목과 저자 정보가 표지·초록·제출 정보에서 일치하는가.
- 목차·쪽번호·표와 그림 번호·본문 참조가 맞는가.
- 본문 인용과 참고문헌이 서로 대응하는가.
- PDF 변환 뒤 한글·수식·표·그림이 잘리거나 바뀌지 않았는가.
- 최종 수정사항이 제출 파일에 반영되었는가.
- 본인에게 적용되는 자격·서식·기한을 확인했는가.

유사도검사 결과는 일치 구절과 인용을 살피는 자료입니다. 특정 비율만으로 표절 여부나 제출 가능 여부를 판단하지 않습니다. [학위·제출 요건](requirements.md) · [실제 사례: 제출 파일에서 확인할 점](case-study.md#submission)
