# 초안에서 제출본까지

김희섭의 석사학위논문 **「고속도로 공사구간 교통안전을 위한 갓길 이동형 로봇 라이다 기반 교통상태 판별 기법 연구」**에서 실제 문장 7쌍을 골랐습니다. 초안의 표현이 제출본에서 어떻게 구체화되었는지, 그 변화에서 무엇을 배울 수 있는지 살펴봅니다.

왼쪽은 **1차 초안 HWP**, 오른쪽은 **20260625 디콜렉션 제출본 PDF**의 발췌입니다. 모바일에서는 초안 다음에 제출본이 이어집니다. 원문의 문구를 유지하되 줄바꿈과 추출 과정의 띄어쓰기를 정리하고, 비교할 부분에 **굵은 글씨**를 더했습니다. 대괄호 번호는 각 판본 안의 표·참고문헌 번호입니다. [비교 자료와 제출본 원문](references.md#case-sources)

같은 논점을 다루는 **서로 다른 절**의 문장을 비교한 사례도 있으므로, 일대일 교정 이력을 뜻하지는 않습니다. ‘달라진 점’은 판본에서 확인한 변화이고, ‘왜 이렇게 고치는가’는 그로부터 배울 작성 원칙입니다. 실제 심사 지시나 저자의 수정 의도를 확인한 설명은 아닙니다.

**달라진 점:** 넓은 표현인 ‘타당성과 실효성’ 대신, 사용할 입력인 **도로영역 차량 객체 데이터**, 검증 환경인 **시험도로**, 확인할 범위인 **적용 가능성**을 적었습니다.

**왜 이렇게 고치는가:** 교통안전은 연구의 큰 목적이지만, 교통상태 분류 결과만으로 사고 감소까지 입증할 수는 없습니다. 목적 문장에서 자료·환경·검증 범위를 밝혀야 독자가 이번 연구가 실제로 답할 질문을 알 수 있습니다.

**내 원고에서 할 일:** 목적 문장에 ‘무엇을 입력으로, 어떤 조건에서, 무엇을 확인했는가’를 넣으세요. ‘실시간’이나 ‘효율 향상’을 주장한다면 이를 뒷받침할 처리시간·자원 사용량 측정도 연결해야 합니다.

**달라진 점:** ‘패러다임의 전환’이라는 큰 이름보다 **기존 데이터의 어느 부분을 어떤 목적으로 활용하는지**가 드러납니다. 제출본은 이 설명을 적용환경·데이터 원천·처리 목적·평가 대상 등의 비교로 연결합니다.

**왜 이렇게 고치는가:** 독자는 ‘새롭다’는 평가보다 기존 연구와 다른 입력·절차·평가를 보고 차별성을 판단합니다. 다만 문장이 구체적이라는 이유만으로 독창성이 입증되지는 않습니다. 비교 대상 문헌의 원문이 그 차이를 뒷받침해야 합니다.

**내 원고에서 할 일:** ‘혁신적’, ‘새로운 접근’ 같은 말 뒤에 실제 차이 한 가지를 적으세요. 예를 들어 사용할 자료, 분석 단위, 검증 조건 중 무엇이 달라지는지 쓰고, 해당 차이를 확인할 선행연구를 연결합니다.

**달라진 점:** 초안 서론의 ROI 진입·이탈 사건 중심 설명과, 제출본의 연속 시점 객체 관측·대표속도 산출 설명이 다릅니다. 여기에는 **기술적 설계의 변경**이 포함됩니다. EWMA 등 일부 안정화 요소는 초안 방법 장에도 있었으므로 제출본에서 모두 새로 생긴 단계로 읽으면 안 됩니다.

**왜 이렇게 고치는가:** 연구 중 방법이 바뀌었는데 서론만 옛 설계를 유지하면, 독자는 어느 방법으로 결과를 얻었는지 알 수 없습니다. 같은 실험을 보기 좋게 서술한 수정과 실제 방법의 변경을 구별하고, 최종 수행 절차에 맞춰 원고 전체를 고쳐야 합니다.

**내 원고에서 할 일:** 입력 → 처리 → 예외 처리 → 출력 순서로 실제 수행한 방법을 적으세요. 그다음 연구질문·절차도·코드와 설정·결과표·초록을 대조합니다. 제출본이 별도로 다루는 `no_data`처럼 출력이 없는 조건도 방법에 포함합니다.

## 04. 결과: 지표의 정의에서 실제 분모로 {#results}

<div class="quote-pair" role="group" aria-label="평가 분모의 원문 비교">
<section class="quote-version" aria-label="평가 분모: 1차 초안">
<p class="quote-label">1차 초안</p>
<blockquote><p>정확도(Accuracy)는 <strong>전체 검증 샘플</strong> 중 올바르게 분류된 비율로 정의된다.</p></blockquote>
<p class="quote-source">3.5.3절 「평가 지표 정의 및 Coverage 기준」</p>
</section>
<section class="quote-version" aria-label="평가 분모: 제출본">
<p class="quote-label">제출본</p>
<blockquote><p>[표 4-11]는 정확도 산정의 분모가 전체 시간창 2,001개가 아니라 <strong>최종 유효 비교쌍 1,283개</strong>인 이유를 보여준다.</p></blockquote>
<p class="quote-source">4.3.3절 · 본문 68쪽 / PDF 87쪽</p>
</section>
</div>

**달라진 점:** 초안 방법 장의 지표 정의가 제출본 결과 장에서는 **실제로 사용한 분석 수와 제외 과정**으로 구체화됩니다. 이 둘은 같은 위치의 문장을 고친 이력이 아니라, 정의가 실제 결과 보고로 연결되는 사례입니다.

**왜 이렇게 고치는가:** ‘전체 검증 샘플’만으로는 수집한 자료 전체인지, 비교 가능한 자료만인지 알 수 없습니다. 독자가 같은 분모로 지표를 다시 계산할 수 있어야 결과의 의미를 판단할 수 있습니다.

제출본 표 4-11을 읽기 쉽게 옮기면 다음과 같습니다. 단위는 차량이나 사람이 아니라 **시간창**입니다.

| 평가기준 레이블 | 제안방법의 유효 출력 | 제안방법의 판별불가(`no_data`) | 합계 |
|---|---:|---:|---:|
| 있음 | 1,283 | 2 | 1,285 |
| 없음 | 634 | 82 | 716 |
| 합계 | 1,917 | 84 | 2,001 |

상태 일치율의 분모는 기준 레이블과 유효 출력이 모두 있는 **1,283개**입니다. 기준 레이블이 있는 구간에서 비교쌍을 확보한 비율 **1,283/1,285 ≈ 99.84%**는 정확도가 아닙니다. 전체 시간창에서 유효 출력이 나온 비율 **1,917/2,001**과도 다릅니다. 분모가 다르면 답하는 질문도 달라집니다.

**내 원고에서 할 일:** 수집 수 → 제외 수와 이유 → 최종 분석 수를 표에 적으세요. `no_data`를 지표에서 제외할 때는 개수와 이유를 함께 보고합니다. 제외 사실을 적는 것만으로 실제 사용에서의 출력 공백 문제가 해결되지는 않습니다.

## 05. 논의: 근거가 허용하는 만큼만 결론 내리기 {#discussion}

### 비교 A. 별도 처리와 독립적인 참값은 같은가

<div class="quote-pair" role="group" aria-label="평가기준과 참값의 원문 비교">
<section class="quote-version" aria-label="평가기준과 참값: 1차 초안">
<p class="quote-label">1차 초안</p>
<blockquote><p>본 연구의 성능 평가는 온라인 시스템과 <strong>독립된 참값(Ground Truth, GT)</strong>을 기준으로 수행된다.</p></blockquote>
<p class="quote-source">3.5.1절 「정답지(GT) 생성 방법」</p>
</section>
<section class="quote-version" aria-label="평가기준과 참값: 제출본">
<p class="quote-label">제출본</p>
<blockquote><p>셋째, 평가기준 상태 레이블은 <strong>외부 독립 계측장비가 제공한 절대 참값이 아니라 원천 DB 기반으로 구성</strong>되었다. 따라서 본 연구에서 제시한 정확도는 절대 참값 대비 정확도가 아니라, 평가기준 상태 레이블과 제안 기법 적용 상태 라벨 간의 <strong>시간창 단위 일치율</strong>로 해석해야 한다.</p></blockquote>
<p class="quote-source">5.3절 「연구의 한계 및 향후 연구」 · 본문 81쪽 / PDF 100쪽</p>
</section>
</div>

**달라진 점:** 초안은 ‘독립된 참값’이라고 부릅니다. 제출본은 기준 레이블의 생성 원천을 밝히고, 결과의 의미를 **외부 참값 대비 정확성에서 기준 레이블과의 일치성**으로 한정합니다.

**왜 이렇게 고치는가:** 별도 프로그램에서 처리했어도 동일한 센서 자료를 사용하면 측정 오류를 함께 가질 수 있습니다. 이때 두 출력이 잘 맞는다는 사실만으로 실제 상태도 정확히 맞혔다고 단정할 수 없습니다. ‘GT’라는 이름보다 자료의 생성 과정과 독립성이 중요합니다.

**내 원고에서 할 일:** 기준 자료를 누가, 무엇으로, 어떤 절차로 만들었는지 적으세요. 제안방법과 공유하는 자료·가정이 있다면 결과 해석에 반영하고, 독립적인 기준과의 검증은 실제 수행 여부를 구분합니다.

**왜 이렇게 고치는가:** 메시지 수나 표현 단위가 줄어도 CPU 사용량·처리시간이 같은 비율로 줄어드는 것은 아닙니다. 이 문장은 계획한 성능 비교가 완료되었다는 뜻이 아닙니다. 한계를 적는 것만으로 미측정 성능의 근거가 채워지지는 않습니다.

**내 원고에서 할 일:** 핵심 성능 주장을 유지하려면 같은 환경의 비교 측정을 추가하세요. 현재 자료로 원고를 마무리한다면 목적·초록·결론에서도 직접 확인한 범위로 표현을 맞춥니다.

## 06. 제출 전: 바뀐 문장을 원고 전체에 반영하기 {#submission}

좋은 수정은 한 문장을 매끄럽게 다듬는 데서 끝나지 않습니다. 앞의 사례처럼 연구의 범위·방법·근거가 달라졌다면 연결된 부분도 함께 확인합니다.

| 고친 내용 | 함께 대조할 부분 |
|---|---|
| 목적과 검증 범위 | 제목, 연구질문, 초록, 결론의 주장 |
| 실제 수행한 방법 | 방법 장, 절차도, 코드와 설정, 실험 조건 |
| 분석 수와 제외 기준 | 자료 설명, 지표의 분모, 표의 합계, 본문의 수치 |
| 평가기준과 해석의 한계 | 결과 해석, 기여, 한계, 후속 연구 |

최종 확인은 **제출할 PDF 자체**로 합니다. 이 사례의 제출본은 디콜렉션 폴더의 111쪽 논문입니다. 자료 중에는 파일명에 ‘최종본’이 들어간 31쪽 발표자료도 있으므로 파일명만으로 판본을 판단하지 않았습니다. 제출본이라는 이름도 내용의 정확성을 보증하지는 않습니다. 인용·참고문헌, 목차·본문, 표·수치, 제목·초록을 끝까지 대조하세요.
