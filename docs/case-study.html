01. 목적: 무엇으로 어디까지 검증하는가

1차 초안

본 연구는 고속도로 공사구간의 교통안전 확보를 위한 갓길 이동형 자율주행 로봇의 활용을 전제로, 엣지 컴퓨팅 환경에 적합한 경량화된 실시간 교통상태 판별 기법의 타당성과 실효성을 검증하고자 한다.

1.4절 「연구 문제 및 구성」 첫 문장

제출본

본 연구의 목적은 고속도로 공사구간의 교통안전 향상을 위한 기초 연구로서, 갓길 이동형 로봇의 자율주행 과정에서 수집되는 LiDAR 센서 데이터 중 도로영역 차량 객체 데이터를 활용하여 교통상태를 판별하는 경량 기법을 제안하고, 시험도로 기반 데이터를 통해 그 적용 가능성을 검증하는 것이다.

1.2절 「연구 목적」 · 본문 3쪽 / PDF 22쪽

달라진 점: 넓은 표현인 ‘타당성과 실효성’ 대신, 사용할 입력인 도로영역 차량 객체 데이터, 검증 환경인 시험도로, 확인할 범위인 적용 가능성을 적었습니다.

왜 이렇게 고치는가: 교통안전은 연구의 큰 목적이지만, 교통상태 분류 결과만으로 사고 감소까지 입증할 수는 없습니다. 목적 문장에서 자료·환경·검증 범위를 밝혀야 독자가 이번 연구가 실제로 답할 질문을 알 수 있습니다.

내 원고에서 할 일: 목적 문장에 ‘무엇을 입력으로, 어떤 조건에서, 무엇을 확인했는가’를 넣으세요. ‘실시간’이나 ‘효율 향상’을 주장한다면 이를 뒷받침할 처리시간·자원 사용량 측정도 연결해야 합니다.

02. 문헌: 큰 차별성을 구체적인 비교로 바꾸기

1차 초안

따라서 본 연구의 필요성은 단순한 기술 고도화가 아니라, 설계 패러다임의 전환에 있다.

2.5절 「선행연구의 한계 및 본 연구의 필요성」

제출본

대신 갓길 이동형 로봇의 자율주행, 장애물 회피, 주변 환경 인식에 사용되는 LiDAR 데이터 중 도로영역 차량 객체 데이터를 교통상태 판별 입력으로 분리 활용한다.

2.3.3절 「본 연구의 차별성」 · 본문 25쪽 / PDF 44쪽

달라진 점: ‘패러다임의 전환’이라는 큰 이름보다 기존 데이터의 어느 부분을 어떤 목적으로 활용하는지가 드러납니다. 제출본은 이 설명을 적용환경·데이터 원천·처리 목적·평가 대상 등의 비교로 연결합니다.

왜 이렇게 고치는가: 독자는 ‘새롭다’는 평가보다 기존 연구와 다른 입력·절차·평가를 보고 차별성을 판단합니다. 다만 문장이 구체적이라는 이유만으로 독창성이 입증되지는 않습니다. 비교 대상 문헌의 원문이 그 차이를 뒷받침해야 합니다.

내 원고에서 할 일: ‘혁신적’, ‘새로운 접근’ 같은 말 뒤에 실제 차이 한 가지를 적으세요. 예를 들어 사용할 자료, 분석 단위, 검증 조건 중 무엇이 달라지는지 쓰고, 해당 차이를 확인할 선행연구를 연결합니다.

03. 방법: 설계 변경을 원고 전체에 반영하기

1차 초안

이를 위해 기존 LiDAR 기반 교통 관측에서 요구되었던 다중 객체 추적(Multi-Object-Tracking) 및 3차원 바운딩 박스 연산을 배제하고, 고정형 관심 영역(ROI)을 통과하는 차량의 진입·이탈 타임스탬프만을 활용하는 이벤트 기반 접근의 적용 가능성을 분석한다.

1.4절 「연구 문제 및 구성」

제출본

속도 관측치는 동일 차량 객체가 연속 시점에서 관측된 경우에 산출하며, 이후 EWMA 기반 안정화, 10 km/h 단위 양자화, 10초 중앙버퍼 기반 대표속도 산출 절차를 거친다.

3.1.1절 「제안하는 기법의 전체 구조」 · 본문 27쪽 / PDF 46쪽

달라진 점: 초안 서론의 ROI 진입·이탈 사건 중심 설명과, 제출본의 연속 시점 객체 관측·대표속도 산출 설명이 다릅니다. 여기에는 기술적 설계의 변경이 포함됩니다. EWMA 등 일부 안정화 요소는 초안 방법 장에도 있었으므로 제출본에서 모두 새로 생긴 단계로 읽으면 안 됩니다.

왜 이렇게 고치는가: 연구 중 방법이 바뀌었는데 서론만 옛 설계를 유지하면, 독자는 어느 방법으로 결과를 얻었는지 알 수 없습니다. 같은 실험을 보기 좋게 서술한 수정과 실제 방법의 변경을 구별하고, 최종 수행 절차에 맞춰 원고 전체를 고쳐야 합니다.

내 원고에서 할 일: 입력 → 처리 → 예외 처리 → 출력 순서로 실제 수행한 방법을 적으세요. 그다음 연구질문·절차도·코드와 설정·결과표·초록을 대조합니다. 제출본이 별도로 다루는 no_data처럼 출력이 없는 조건도 방법에 포함합니다.

04. 결과: 지표의 정의에서 실제 분모로

1차 초안

정확도(Accuracy)는 전체 검증 샘플 중 올바르게 분류된 비율로 정의된다.

3.5.3절 「평가 지표 정의 및 Coverage 기준」

제출본

[표 4-11]는 정확도 산정의 분모가 전체 시간창 2,001개가 아니라 최종 유효 비교쌍 1,283개인 이유를 보여준다.

4.3.3절 · 본문 68쪽 / PDF 87쪽

달라진 점: 초안 방법 장의 지표 정의가 제출본 결과 장에서는 실제로 사용한 분석 수와 제외 과정으로 구체화됩니다. 이 둘은 같은 위치의 문장을 고친 이력이 아니라, 정의가 실제 결과 보고로 연결되는 사례입니다.

왜 이렇게 고치는가: ‘전체 검증 샘플’만으로는 수집한 자료 전체인지, 비교 가능한 자료만인지 알 수 없습니다. 독자가 같은 분모로 지표를 다시 계산할 수 있어야 결과의 의미를 판단할 수 있습니다.

제출본 표 4-11을 읽기 쉽게 옮기면 다음과 같습니다. 단위는 차량이나 사람이 아니라 시간창입니다.

평가기준 레이블 제안방법의 유효 출력 제안방법의 판별불가(no_data) 합계
있음 1,283 2 1,285
없음 634 82 716
합계 1,917 84 2,001

상태 일치율의 분모는 기준 레이블과 유효 출력이 모두 있는 1,283개입니다. 기준 레이블이 있는 구간에서 비교쌍을 확보한 비율 1,283/1,285 ≈ 99.84%는 정확도가 아닙니다. 전체 시간창에서 유효 출력이 나온 비율 1,917/2,001과도 다릅니다. 분모가 다르면 답하는 질문도 달라집니다.

내 원고에서 할 일: 수집 수 → 제외 수와 이유 → 최종 분석 수를 표에 적으세요. no_data를 지표에서 제외할 때는 개수와 이유를 함께 보고합니다. 제외 사실을 적는 것만으로 실제 사용에서의 출력 공백 문제가 해결되지는 않습니다.

05. 논의: 근거가 허용하는 만큼만 결론 내리기

비교 A. 별도 처리와 독립적인 참값은 같은가

1차 초안

본 연구의 성능 평가는 온라인 시스템과 독립된 참값(Ground Truth, GT)을 기준으로 수행된다.

3.5.1절 「정답지(GT) 생성 방법」

제출본

셋째, 평가기준 상태 레이블은 외부 독립 계측장비가 제공한 절대 참값이 아니라 원천 DB 기반으로 구성되었다. 따라서 본 연구에서 제시한 정확도는 절대 참값 대비 정확도가 아니라, 평가기준 상태 레이블과 제안 기법 적용 상태 라벨 간의 시간창 단위 일치율로 해석해야 한다.

5.3절 「연구의 한계 및 향후 연구」 · 본문 81쪽 / PDF 100쪽

달라진 점: 초안은 ‘독립된 참값’이라고 부릅니다. 제출본은 기준 레이블의 생성 원천을 밝히고, 결과의 의미를 외부 참값 대비 정확성에서 기준 레이블과의 일치성으로 한정합니다.

왜 이렇게 고치는가: 별도 프로그램에서 처리했어도 동일한 센서 자료를 사용하면 측정 오류를 함께 가질 수 있습니다. 이때 두 출력이 잘 맞는다는 사실만으로 실제 상태도 정확히 맞혔다고 단정할 수 없습니다. ‘GT’라는 이름보다 자료의 생성 과정과 독립성이 중요합니다.

내 원고에서 할 일: 기준 자료를 누가, 무엇으로, 어떤 절차로 만들었는지 적으세요. 제안방법과 공유하는 자료·가정이 있다면 결과 해석에 반영하고, 독립적인 기준과의 검증은 실제 수행 여부를 구분합니다.

비교 B. 계획한 경량화와 실제 측정은 일치하는가

1차 초안

둘째, 제안 알고리즘이 ARM 기반 엣지 환경에서 기존 추적 기반 방식 대비 처리 지연과 CPU 점유율을 실무 적용 가능한 수준으로 저감할 수 있는지를 분석한다.

1.4절 「연구 문제 및 구성」 두 번째 검증 과제

제출본

object input 메시지가 state output 메시지 및 시간창 단위 상태 라벨로 축약되는 데이터 표현 단위 감소는 확인하였으나, 실제 저장용량, CPU·메모리 사용량, 네트워크 전송 및 처리 지연시간은 직접 측정하지 않았다.

5.3절 「연구의 한계 및 향후 연구」 · 본문 81쪽 / PDF 100쪽

달라진 점: 초안은 기존 방식 대비 자원 사용량과 지연을 비교할 계획을 제시합니다. 제출본은 실제 확인한 데이터 표현 단위 감소와 직접 측정하지 않은 자원 성능을 구분합니다.

왜 이렇게 고치는가: 메시지 수나 표현 단위가 줄어도 CPU 사용량·처리시간이 같은 비율로 줄어드는 것은 아닙니다. 이 문장은 계획한 성능 비교가 완료되었다는 뜻이 아닙니다. 한계를 적는 것만으로 미측정 성능의 근거가 채워지지는 않습니다.

내 원고에서 할 일: 핵심 성능 주장을 유지하려면 같은 환경의 비교 측정을 추가하세요. 현재 자료로 원고를 마무리한다면 목적·초록·결론에서도 직접 확인한 범위로 표현을 맞춥니다.

비교 C. 일반적인 분포와 내 평가셋을 구분했는가

1차 초안

그러나 고속도로 연속류 데이터는 원활(Free) 상태의 비중이 상대적으로 높고, 서행(Slow) 및 정체(Congested) 상태의 발생 빈도는 낮은 경향이 있다 [27].

3.5.3절 「평가 지표 정의 및 Coverage 기준」

제출본

둘째, 평가셋의 상태 분포가 정체 상태에 편중되어 원활 및 서행 상태의 판별 성능을 충분히 검증하지 못하였다. 전체 정확도와 Weighted-F1은 높게 나타났으나, 이는 정체 상태의 높은 표본 비중이 반영된 결과이다.

5.3절 「연구의 한계 및 향후 연구」 · 본문 81쪽 / PDF 100쪽

달라진 점: 초안의 문장은 인용 문헌에 기대어 일반적인 고속도로 교통 분포를 설명합니다. 제출본의 문장은 실제 평가셋의 분포와 그 한계를 설명합니다. 같은 자료의 분포가 원활에서 정체로 뒤집혔다는 비교가 아닙니다.

왜 이렇게 고치는가: 전체 지표가 높아도 표본이 적은 상태의 성능까지 충분히 확인한 것은 아닙니다. 내 자료가 어떤 조건에 치우쳐 있는지 보여줘야 독자가 결과를 적용할 수 있는 범위를 판단할 수 있습니다.

내 원고에서 할 일: 상태·집단·조건별 표본 수와 성능을 함께 보세요. 관측이 부족한 조건은 별도로 밝히고, 전체 평균을 모든 조건의 성능으로 일반화하지 않습니다.
