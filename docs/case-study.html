초안에서 제출본까지

김희섭의 석사학위논문 「고속도로 공사구간 교통안전을 위한 갓길 이동형 로봇 라이다 기반 교통상태 판별 기법 연구」를 통해 원고가 구체화되는 과정을 살펴봅니다. 완성된 논문의 목차를 따라 쓰기보다, 질문·방법·결과·결론이 어떻게 맞춰지는지 읽어보세요.

비교 기준은 1차 초안 HWP와 ‘디콜렉션 제출본’의 20260625 PDF입니다. 중간 초안도 함께 대조했습니다. 아래 원고의 변화는 실제 판본에서 확인한 내용이고, 배울 점은 이를 바탕으로 정리한 작성 지침입니다. 비교 자료와 제출본 원문

01. 큰 목적을 확인할 수 있는 질문으로 바꾸기

초안에는 무엇이 있었나

1차 초안은 공사구간의 교통안전을 배경으로 초경량 실시간 교통상태 판별을 제안합니다. 연구문제에는 타임스탬프를 이용한 속도 추정, ARM 기반 환경에서 기존 추적 방식 대비 처리 지연·CPU 점유율 감소, 상태 요동 억제가 포함되어 있습니다.

물리적인 로봇 주행 제어는 초안에서도 제외했습니다. 따라서 이 사례의 변화는 “로봇 제어를 뒤늦게 뺐다”가 아닙니다. 검증할 입력과 결과, 실험 조건을 더 명확하게 맞춘 과정입니다.

제출본에서는 어떻게 달라졌나

제출본은 기존 자율주행 라이다 데이터 중 도로영역 차량 객체 정보를 활용하는 것으로 대상을 구체화했습니다. 연구질문도 입력 구성, 대표속도 안정화, 기준 레이블과의 일치성, 오분류·판별불가 조건으로 나눴습니다. 실제 평가 환경은 시험도로이며, 사고 감소·운전자 경고 효과·장기 현장 실증은 직접 검증한 범위에서 제외했습니다. 출처: 제출본 1.2–1.3절, 본문 3–5쪽(PDF 22–24쪽).

초안에서 확인한 방향 제출본에서 확인한 범위
초경량·실시간 판별의 효율성과 정확도 검증 시험도로 데이터에서 상태 판별의 적용 가능성 검토
처리 지연·CPU 점유율 비교 계획 실제 측정한 표현 단위 축소와 출력 특성, 미측정 자원 성능의 구분
교통안전이라는 넓은 배경 상태 판별 결과와 안전 효과를 구별한 연구 범위

배울 점: 배경에서 해결하고 싶은 큰 문제와, 이번 논문에서 직접 답한 질문을 구분합니다. “안전을 높인다”, “효율을 개선한다”는 표현을 쓰려면 무엇을 측정했는지 이어서 설명할 수 있어야 합니다.

내 원고에 적용: 제목과 연구질문의 핵심 단어마다 자료·평가표를 연결해 보세요. 연결할 근거가 없다면 추가 검증을 하거나 주장 범위를 조정합니다.

02. 관련연구를 내 연구의 비교 기준으로 정리하기

초안에는 무엇이 있었나

초안의 관련연구에는 교통상태 정의, 공사구간의 구성과 위험 요인, 고정식·이동형 교통 관측 등이 담겨 있습니다. 교통상태 판별이 필요한 배경과 기존 관측 방법을 설명하는 데 상당한 분량을 사용합니다.

제출본에서는 어떻게 달라졌나

제출본 2.3.3절과 표 2-6은 선행연구와 본 연구를 적용환경·데이터 원천·활용 데이터·처리 목적·판별 방식·평가 대상·제외 범위로 나란히 비교합니다. 예를 들어 객체검출이나 위험도 산정과, 이미 얻은 차량 객체 정보를 대표속도·상태로 바꾸는 연구의 차이를 드러냅니다. 출처: 본문 25–26쪽(PDF 44–45쪽).

배울 점: 문헌의 수를 늘리는 것만으로 차별성이 생기지는 않습니다. 내 연구질문에 필요한 비교 기준을 정하고, 각 문헌이 그 기준에서 무엇을 보여주는지 묶어 써야 합니다. 비교표의 요약도 개별 원문으로 뒷받침해야 합니다.

내 원고에 적용: 문헌마다 질문·자료·방법·결과·한계를 적은 뒤, 여러 연구에서 반복되는 한계와 내 연구가 다룰 한계를 구분합니다. “기존 연구는 모두 부족하다”는 식의 일괄 평가를 피하세요.

03. 방법이 바뀌면 원고 전체를 함께 고치기

초안에는 무엇이 있었나

1차 초안의 목적·연구문제는 ROI 진입·이탈 타임스탬프를 통한 속도 산출과 다수결 슬라이딩 윈도우를 중심으로 설명합니다. 방법 본문에는 다른 안정화 요소도 함께 등장하므로, 초안의 서론과 방법이 완전히 일치한다고 가정해서는 안 됩니다.

제출본에서는 어떻게 달라졌나

제출본은 도로영역 객체 선별 → 연속 위치 변화로 속도 표본 생성 → 최근 표본 집계 → EWMA 안정화 → 10km/h 단위 양자화 → 10초 중앙버퍼 기반 대표속도 → 상태 출력의 절차를 설명합니다. 판별할 수 없는 경우는 no_data로 구분합니다. 출처: 1.2절과 제3장, 본문 3쪽·27쪽 이하(PDF 22쪽·46쪽 이하).

이 변화에는 기술적 설계의 변경이 포함됩니다. 같은 실험을 더 매끄럽게 표현한 것으로만 읽으면 안 됩니다. 최종 방법과 일치하는 코드·설정·자료·결과인지 별도로 대조해야 합니다.

배울 점: 방법 장에는 입력, 처리 단계, 변수와 단위, 설정 근거, 예외 처리, 출력을 적습니다. 연구 중 방법이 바뀌었다면 서론의 연구질문, 그림, 평가 기준, 초록, 결론까지 영향을 확인합니다.

내 원고에 적용: 제안방법을 입력부터 출력까지 한 줄로 적고, 각 단계가 원고의 어느 절과 실제 분석의 어느 부분에 대응하는지 확인하세요. 설문 연구라면 개념 → 문항 → 응답 → 점수 → 분석의 연결을 같은 방식으로 확인합니다.

04. 결과 장의 빈 목차를 근거가 있는 설명으로 채우기

초안에는 무엇이 있었나

1차 초안의 결과 장에는 ‘실험 시나리오’, ‘데이터셋 구성’, ‘등급별 분류’, ‘실시간성’, ‘오분류 사례’ 등의 제목이 남아 있습니다. 분석할 항목을 잡아 둔 상태이며, 그 자체로 결과가 입증되지는 않습니다.

제출본에서는 어떻게 달라졌나

제출본은 전체 시간창과 실제 비교에 사용한 시간창을 분리합니다. 표 4-11을 읽기 쉽게 옮기면 다음과 같습니다. 출처: 본문 68쪽(PDF 87쪽). 단위는 차량이나 사람이 아니라 시간창입니다.

평가기준 레이블 제안방법의 유효 출력 제안방법의 판별불가(no_data) 합계
있음 1,283 2 1,285
없음 634 82 716
합계 1,917 84 2,001

상태 일치율의 분모는 전체 2,001개가 아니라, 기준 레이블과 유효 출력이 모두 있는 1,283개입니다. 반면 유효 출력 여부는 전체 2,001개 중 1,917개를 대상으로 볼 수 있습니다. 기준 레이블이 있는 구간에서 비교쌍을 확보한 비율 1,283/1,285(약 99.84%)와도 다른 값입니다. 분모가 다르면 답하는 질문도 달라집니다.

no_data를 분류 지표에서 제외할 때는 몇 개를 왜 제외했는지 함께 보여줘야 합니다. 판별불가를 따로 보고한다고 해서 실제 사용에서 발생하는 출력 공백의 문제가 해결되는 것은 아닙니다.

배울 점: “정확도가 높다”는 한 문장보다 어떤 자료를 얼마나 사용했고, 무엇과 비교했으며, 제외한 자료는 무엇인지 먼저 보여줍니다. 이후 전체 결과와 함께 상태별 성능·실패 조건을 설명합니다.

내 원고에 적용: 수집 수 → 제외 수와 이유 → 최종 분석 수를 적으세요. 설문에서는 응답자 수와 문항 응답 수를, 실험에서는 장면·대상·반복 실행 수를 구분합니다. 숫자가 많은 것과 독립적인 근거가 많은 것은 다릅니다.

05. 계획했던 주장과 실제 얻은 근거를 구분하기

비교 A. ‘참값’이라고 부를 수 있는가

초안 3.5.1절에는 다음과 같은 표현이 있습니다.

본 연구의 성능 평가는 온라인 시스템과 독립된 참값(Ground Truth, GT)을 기준으로 수행된다.

그러나 설명된 기준 자료도 센서 로그에서 재구성됩니다. 별도의 프로그램에서 처리했다는 사실과, 측정 원천이 독립적이라는 사실은 구분해야 합니다.

제출본 5.3절은 평가기준이 외부 독립 계측장비의 절대참값이 아니라 원천 DB에서 구성한 레이블이라고 밝힙니다. 결과를 기준 레이블과 제안방법 출력 사이의 시간창 단위 일치율로 해석하고, 독립적인 기준 자료를 이용한 후속 검증을 제안합니다. 출처: 본문 81쪽(PDF 100쪽).

비교 B. ‘경량화’를 어디까지 확인했는가

초안은 기존 MOT 방식과 처리 지연·CPU 점유율을 비교할 계획을 제시합니다. 제출본 3.5.5절·5.3절은 표현 단위와 출력 수의 축소를 설명하면서 CPU·메모리·저장용량·전송 및 처리 지연은 직접 측정하지 않았다고 명시합니다. 출처: 본문 51쪽·81–82쪽(PDF 70쪽·100–101쪽).

표현 단위가 줄었다고 처리시간까지 같은 비율로 줄어드는 것은 아닙니다. 실시간성이나 자원 효율을 주장하려면 해당 환경에서 직접 측정한 근거가 추가로 필요합니다.

비교 C. 높은 전체 성능을 어떻게 해석하는가

제출본은 정체 상태가 많은 평가셋이라는 점을 한계에 적고, 전체 정확도와 Weighted-F1이 상태 분포의 영향을 받는다고 설명합니다. 원활·서행을 포함한 다양한 조건과 실제 공사구간으로 결론을 넓히려면 추가 검증이 필요하다고 정리합니다. 출처: 본문 81쪽(PDF 100쪽).

배울 점: 한계는 논문 끝에 붙이는 상투적인 문장이 아닙니다. 결과가 답할 수 있는 범위를 정하는 설명입니다. 다만 한계를 적었다고 불완전한 비교나 자료 부족이 해결되지는 않습니다. 핵심 주장을 유지하려면 추가 검증이 필요하고, 현재 근거로 충분하지 않다면 표현을 줄여야 합니다.

내 원고에 적용: 결론의 문장마다 ‘직접 관측한 결과 / 결과에서 해석한 의미 / 앞으로 검증할 가능성’을 나눠 보세요. 이 세 가지가 한 문장 안에서 섞이면 다시 씁니다.

06. 제출 파일은 내용과 형식을 함께 확인하기

초안에는 글꼴·크기 안내, 채워지지 않은 영문 제목, 결과 장의 빈 절 등 작성 중 흔적이 남아 있습니다. 제출 단계에서는 이 흔적을 정리하고, 실제 결과가 들어간 본문·초록·목차·표 목록을 맞춰야 합니다.

이번 자료에는 파일명에 ‘최종본’이 들어가지만 31쪽 발표자료인 PDF도 있었습니다. 사례의 제출본은 별도로 보관된 디콜렉션 폴더의 111쪽 PDF입니다. 이름만 보고 비교 대상을 정하면 발표자료와 논문을 혼동할 수 있습니다.

배울 점: 제출본이라는 이름이 원고 전체의 정확성을 보증하지 않습니다. 인용과 참고문헌, 목차와 본문, 계산 결과와 표, 제목과 초록을 마지막으로 대조하세요. PDF로 변환한 파일도 직접 열어 확인합니다.

내 원고에 적용: 수정할 때마다 ‘어느 문장을 어떻게 고쳤는가’와 함께 ‘그 수정으로 달라져야 하는 표·초록·결론은 무엇인가’를 확인하세요. 최종 파일은 제출할 파일 자체를 열어 점검합니다.
