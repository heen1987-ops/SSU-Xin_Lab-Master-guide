# 문헌 검색과 데이터

## 1. 문제정의 — 공백을 명확히 하기

"AI가 요즘 중요하다"는 현상의 중요성과 "기존 방법이 이 조건에서 실패한다"는 학술적 공백은 다릅니다. 서론을 쓰기 전에 아래를 정리합니다.

- 기존 방법들이 이미 해결한 것은 무엇인가.
- 어떤 조건·데이터·규모에서 기존 방법이 부족한가(성능, 효율, 일반화, 해석가능성 등).
- 내가 제안하려는 방법이 그 공백을 어떻게 메우는가.

주장-근거 표를 만들어 각 문장에 실제 출처를 연결합니다. 근거 없는 문장은 `[확인 필요]`로 남깁니다.

## 2. 문헌 검색

Google Scholar, 국내 학회지, SCI/SCIE·해외 학술지에서 실제로 검색합니다. 검색어·검색일·검색 범위를 기록하고, **실제 API/웹 검색으로 확인한 것**과 **브라우저로 직접 확인한 것**을 구분합니다. 학술지/학술대회, 색인(SCI/SCIE, Q등급 등) 여부도 각각 기록합니다.

- 초록만 읽은 상태를 "원문 검수 완료"로 표시하지 않습니다.
- 검색을 일부만 했으면 "관련 연구가 없다"고 단정하지 않습니다.
- 스캔된 PDF의 텍스트를 봐야 하면 OCR·원문 검수 절차를 거칩니다(단순 텍스트 추출은 원문 독해 완료가 아닙니다).

## 3. 데이터셋 검색과 점검

`검색 → 후보 카드 → 실제 점검 → 프로토콜`의 흐름으로 진행합니다.

- 검색으로 찾은 모든 후보는 일단 "후보"로 표시하고, 검토 없이 "적합" 또는 "검증 완료"로 승격하지 않습니다.
- 검색 순위·인기도·다운로드 수를 데이터 품질이나 대표성의 증거로 바꾸지 않습니다.
- 공공 데이터, 저장소(GitHub 등), 커뮤니티, 대학, 직접 수집 데이터를 함께 고려하되, 같은 원본의 미러본·fork·파생본을 서로 다른 독립 데이터로 세지 않습니다.
- 결측·중복·그룹 구조·시간적 편향(누수)을 실제로 점검합니다.
- 코드의 라이선스와 데이터의 이용 조건을 별도로 확인합니다.

## 4. 확인해야 할 함정

- 여러 데이터셋을 썼다고 다양성이 자동으로 확보되는 것은 아닙니다. 조건이 안 맞으면 합치지 않습니다.
- 같은 저자·같은 팀의 반복 실험을 독립적인 새 검증처럼 세지 않습니다.
- 자동 평가지표(BLEU, F1 등)의 통과가 사람이 판단하는 품질과 항상 같지는 않습니다.
