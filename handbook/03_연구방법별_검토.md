# 연구방법별로 무엇을 검토할 것인가

먼저 RQ별로 **대상 → 분석단위 → 자료 → 비교·측정 → 분석 → 허용되는 결론**을 연결합니다. 방법 이름보다 이 연결을 읽고 누락을 찾습니다. 이 저장소의 실증·실험 구분은 안내 경로이며 서로 배타적인 학문 분류가 아닙니다.

## 1. 방법별 필수 확인 자료

| 연구 형태 | 검토에 가져올 자료 | 주요 확인 | 흔히 생기는 과장 |
|---|---|---|---|
| 설문·관찰·2차 자료 | 이론·개념 정의, 문항/변수 출처, 표집·결측·제외 기록, 분석 계획·결과 | 측정 타당성, 자료 선택 편향, 분석단위·시점, 교란과 추론 한계 | 의도를 행동으로, 연관성을 인과로 표현 |
| 처치·현장 실험 | 배정·대조 조건, 시행 절차, 처치 이행·탈락 기록, 분석 계획 | 배정·측정·간섭·준수 조건, 효과 추정 대상 | 단순 전후 차이를 처치 효과로 단정 |
| 알고리즘·모델 평가 | 데이터 계보·분할, 비교군 구현·튜닝, 실행환경·로그·평가지표 | 누수, 비교 예산, 독립 단위, 집계·불확실성, 실패 조건 | 유리한 최고값만 보고하거나 한 데이터의 개선을 일반화 |
| 시스템·네트워크 | 부하·장비·환경, 예열·측정 구간, 반복·실행 순서, 오류 로그 | 처리량·지연·비용의 측정 경계와 포화 조건 | 서로 다른 부하·장비의 수치를 직접 비교 |
| 질적·사례 연구 | 사례·참여자 선정 이유, 자료수집 절차, 분석 메모·코딩·해석 근거 | 질문에 맞는 접근, 연구자 위치, 반대 사례, 해석의 추적 가능성 | 일부 발화를 전체 집단의 빈도나 인과 증거로 확대 |
| 시뮬레이션 | 가정·모델·파라미터 근거, 검증 자료, 시나리오·민감도 결과 | 모델 구현 검증, 현실과의 대응 범위, 불확실성 | 모델 내부 결과를 현장 효과로 단정 |
| 이론·증명 | 정의·가정·명제, 증명 단계, 기존 정리와 반례 | 논리적 의존성, 빠진 조건, 적용·복잡도 범위 | 계획한 증명을 완료한 것으로 표현 |
| 혼합·복수 연구 | 연구별 위 자료와 통합 질문·연결표 | 단위·증거 수준의 차이, 연결 논리, 불일치 결과 | 기술 성능을 사람·조직 효과로 대체 |

이 표는 검토 질문의 출발점입니다. 개별 분석의 적합성은 해당 방법의 원전·공식 도구 설명과 실제 자료 조건을 확인해야 합니다. 질적·시뮬레이션·이론 연구의 상세 분석 도구는 이 저장소에서 제공하지 않습니다.

## 2. 실증연구 검토 순서

1. 이론이 설명할 대상과 결과를 확인합니다. 이론 이름을 나열하는 대신 메커니즘과 대안 이론을 비교합니다.
2. 개념 정의와 측정이 일치하는지 봅니다. 번역·축약·변경한 문항은 원척도와 변경 근거를 연결합니다.
3. 모집단·표집틀·모집 경로·선정·제외·결측을 확인합니다. 표본 수는 추론 목표와 설계 근거로 정합니다.
4. 분석단위, 반복·군집 구조, 모형 가정과 주·부 분석을 확인합니다. 결과를 본 뒤 바뀐 분석은 시점과 이유를 남깁니다.
5. 결과·불확실성·강건성·대안 설명을 읽고 주장 범위를 조정합니다. 유의성 하나로 이론의 참·거짓을 결정하지 않습니다.

세부 양식은 [21 실증설계](../21_실증설계와_분석계획.md), 설문 중심의 상세 안내는 [실증 트랙](../01_실증트랙_경영IS/00_트랙개요.md)에서 확인합니다. 탐색적 PCA 지표·복합점수 회귀를 정식 CFA·SEM·인과 추정으로 대체하지 않습니다.

## 3. 공학·실험연구 검토 순서

1. RQ별 비교군과 지표가 제안의 차이를 검증하는지 확인합니다. 최신성·강도·재현 가능성에 따라 비교군 선정 이유를 남깁니다.
2. 평가 데이터의 출처·시점·파생 관계와 분할을 확인합니다. 사용자·문서·기관 등 같은 원천의 자료가 겹치는지 점검합니다.
3. 하드웨어·소프트웨어·튜닝·학습·추론 예산과 측정 경계를 비교합니다. 방법상 다른 자원은 차이와 영향을 보고합니다.
4. 실행 로그에서 결과표로 이어지는 집계 경로를 확인합니다. seed 반복, 질의, 장비 실행 등을 어떤 단위로 추론하는지 구분합니다.
5. 핵심 구성의 기여, 오류 유형, 비용·성능의 관계, 경계조건을 확인합니다. 모든 연구에 동일한 ablation이나 학습 분할을 강제하지 않습니다.

세부 안내는 [실험설계와 방법론 팩](../02_실험트랙_공학컴공/03_실험설계와방법론팩.md), 결과 검토는 [실험 비교·오류 분석](../12_단계별_지침_라이브러리/11_실험비교_Ablation_오류분석.md)을 연결합니다.

## 4. 혼합연구를 통합할 때

공통 문제와 문헌은 공유하되 연구마다 RQ·자료·분석단위·실행상태를 기록합니다. 혼합연구라면 두 종류의 근거가 왜 필요한지, 어떤 순서 또는 지점에서 통합하는지 먼저 설명합니다. 기술 평가와 사용자 연구가 단순히 병렬로 존재한다는 사실만으로 통합된 결론이 생기지는 않습니다.

| 통합 질문 | 연구 A의 근거 | 연구 B의 근거 | 연결할 수 있는 결론 | 남은 제한 |
|---|---|---|---|---|
| [실제 질문] | [단위·조건·결과] | [단위·조건·결과] | [두 결과가 함께 지지하는 범위] | [불일치·미확보·추가 검증] |

## 5. 근거가 부족할 때의 산출물

자료가 없으면 검토할 설계, 확보할 근거, 결과표의 열·단위, 판단 가능한 해석을 작성합니다. 실행하지 않은 결과 수치를 채우지 않습니다. 원문을 읽지 못했다면 문헌 후보와 확인할 주장을 구분해 남깁니다.

지적에는 [검토와 수정 서식](../templates/03_검토와수정.md)을 사용합니다. 추가 분석의 이유·입력·판단 기준을 정한 뒤 실행하고, 코드가 정상 종료된 사실과 분석의 적절성을 따로 검토합니다.
