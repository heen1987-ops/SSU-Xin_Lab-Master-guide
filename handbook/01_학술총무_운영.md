# 학술총무의 논문 검토 운영

학술총무는 학생이 다음 판단에 필요한 원고와 근거를 갖추도록 돕고, 검토 요청·수정·일정을 이어 주는 역할을 맡습니다. 논문 내용의 책임은 연구자에게 있으며, 연구 방향에 대한 지도와 공식 심사·학사 판정은 각 담당 체계에서 이루어집니다.

아래는 신랩 운영안입니다. 운영 주기·검토량·회신일은 참여자와 합의하여 조정합니다.

## 1. 역할과 판단의 경계

| 담당 | 직접 수행할 일 | 기록할 결과 |
|---|---|---|
| 연구자 | 원문 독해, 설계·실행·집필, 질문과 수정 답변 준비 | 판본이 있는 원고·근거·검토 요청서 |
| 학술총무 | 요청 범위 정리, 논리·근거·형식의 누락 확인, 일정·쟁점 관리 | 검토 의견, 다음 산출물, 재검토 상태 |
| 지도교수 | 연구 방향·범위·학술적 기여 지도, 해당 절차의 확인 | 실제 전달받은 의견과 조건·확인일 |
| 방법 자문자 | 합의한 범위에서 통계·시스템·질적 방법 등을 자문 | 자문 근거와 적용 조건, 연구자의 반영 판단 |
| 학과·대학원·심사위원회 | 각 규정에 따른 자격·절차·심사 판단 | 공식 공지·서식·결과·접수 증빙 |

학술총무가 작성한 “검토 완료”는 지정한 파일과 범위를 읽었다는 뜻입니다. 지도교수 확인, 심사 통과, 제출 자격 충족과는 별도 필드로 관리합니다.

## 2. 처음 받을 자료

[검토 요청서](../templates/01_검토요청.md)에 다음 정보를 받습니다.

1. 연구자 식별코드, 과정, 제출 목표, 현재 단계와 연구방법.
2. 연구질문·기여 후보·자료 확보 상태를 요약한 설명.
3. 이번에 읽을 파일명과 판본, 장·절·쪽 또는 표·그림 위치.
4. 결정이 필요한 질문과 원하는 결과물, 희망 회신일.
5. 지난 의견에 대한 변경 요약과 미해결 항목.

주제 탐색 단계에는 완성 원고를 요구하지 않습니다. 주제 설명과 접근 가능한 자료만으로 상담을 시작하고, 없는 정보는 미정으로 둡니다. 원고 검토를 요청했다면 대상 판본과 범위는 확인한 후 읽습니다.

공유 저장소에는 빈 서식과 익명화한 교육 예시만 둡니다. 학생별 원고·현황·연락처·실제 심사의견은 접근이 제한된 연구실 공간에서 관리합니다. 공개 현황표에 내부 저장소의 비공개 링크나 참여자 정보를 그대로 옮기지 않습니다.

## 3. 접수부터 재검토까지

| 순서 | 학술총무가 할 일 | 남길 것 | 다음 행동 |
|---|---|---|---|
| 접수 | 파일·범위·질문·회신일 확인 | 요청 ID, 원고 판본 | 부족한 입력만 요청 |
| 우선순위 조정 | 공식 마감과 선행 작업, 진행을 막는 쟁점 확인 | 검토 순서와 근거 | 회신 가능일 합의 |
| 내용 검토 | 질문→문헌→방법→결과→결론의 연결 확인 | 위치가 있는 지적·수정 요청 | 연구자에게 전달할 의견 확정 |
| 지도 쟁점 정리 | 범위 변경·방법 선택 등 결정이 필요한 항목 구분 | 선택지·근거·영향 | 연구자가 지도교수와 확인 |
| 수정 접수 | 답변표와 새 원고의 변경 위치 대조 | 수용·설명·보류 및 근거 | 영향받는 부분 재검토 |
| 마감·인계 | 이번 검토 범위와 남은 항목 기록 | 다음 산출물·담당·기한 | 현황판 갱신 |

공식 마감이 임박한 요청, 수집·분석을 막는 설계 문제, 결과 해석에 영향을 주는 근거 문제를 먼저 봅니다. 단순 선착순이나 학위과정만으로 순서를 고정하지 않습니다. 읽을 수 있는 양을 넘으면 검토 범위를 줄이거나 회신일을 조정하고 일부만 읽은 사실을 남깁니다.

## 4. 원고를 읽는 순서

먼저 표를 채우지 말고 이번 원고가 무엇을 주장하며 어디서 설득력이 끊기는지 짧게 적습니다. 다음 순서로 근거를 확인한 뒤 빠진 항목을 점검표에 보완합니다.

- **문제·기여:** 연구질문이 실제로 답할 수 있는 형태인가? 가장 가까운 연구와 어떤 지식 차이가 남는가?
- **방법:** 자료·분석단위·비교·측정·가정이 질문에 맞는가? 대안 설명이나 실패 조건을 다루는가?
- **근거:** 핵심 인용의 원문 위치와 실제 결과의 생성 경로가 있는가? 계획·관측·해석이 구분되는가?
- **논증:** 결과가 RQ에 답하는가? 초록·표·본문·결론이 같은 범위를 말하는가?
- **표현·서식:** 앞의 내용이 정리된 범위에서 문단·용어·표·인용·제출 형식을 다듬는다.

[방법별 검토](03_연구방법별_검토.md)를 적용하고 관련 없는 항목은 이유와 함께 제외합니다. 파일이 없다는 사실과 설계가 잘못되었다는 판단을 구분합니다.

## 5. 실행 가능한 의견 쓰기

좋은 의견은 **위치 → 관찰 → 영향 → 요청 작업 → 다시 확인할 근거**가 연결됩니다.

> 교육용 가상 예시: 원고 v0.3, 결과 절의 “이용 의도가 실제 이용을 증가시켰다”는 문장은 설문에서 측정한 의도를 실제 행동으로 확대합니다. 측정한 변수와 설계가 허용하는 관계로 문장을 수정하고, 초록·결론의 동일 표현도 확인하세요. 재검토 때 문항표와 수정된 세 위치를 함께 제출하세요.

“논리가 약함”, “박사답게 보완”, “최신 문헌 추가”만으로 끝내지 않습니다. 무엇을 설명하지 못했는지와 어떤 근거가 있어야 판단할 수 있는지를 적습니다.

| 우선도 | 의미 | 처리 |
|---|---|---|
| 진행 차단 | 자료 권한·윤리 조건 미충족, 핵심 결과 출처 불명 등 현재 작업을 계속하기 어려운 문제 | 영향받는 작업을 보류하고 담당자와 확인 |
| 핵심 보완 | RQ·기여·설계·해석을 바꾸는 문제 | 문장 교정에 앞서 설계·근거·주장 수정 |
| 표현 보완 | 핵심 결론을 바꾸지 않는 용어·구성·서식 문제 | 정해진 판본에서 수정 후 확인 |
| 판단 대기 | 현재 자료로 판단할 수 없음 | 필요한 파일·질문·확인자를 지정 |

합계 점수로 핵심 문제를 상쇄하지 않습니다. 비판 강도는 학생의 과정이 아니라 문제의 영향으로 정합니다.

## 6. 수정·재검토 상태 관리

요청 상태는 **접수 / 자료 보완 / 검토 중 / 의견 전달 / 수정 중 / 재검토 중 / 범위 내 완료 / 보류**로 구분합니다. 개별 의견은 **미착수 / 조치 중 / 재검토 대기 / 확인 완료 / 설명 수용 / 보류**로 관리합니다.

연구자가 “수정 완료”라고 답하면 재검토 대기로 옮깁니다. 검토자가 새 원고와 근거를 대조한 뒤 확인 완료로 바꿉니다. 의견에 동의하지 않을 때도 근거 있는 설명과 판단을 기록합니다. AI 자기점검, 동료 검토, 지도교수 확인은 수행자와 성격을 명시합니다.

새 자료·방법·결과로 결론이 바뀌면 관련된 이전 의견을 다시 엽니다. 이번 검토를 종료할 때는 **읽은 범위·최신 판본·남은 쟁점·다음 담당**을 명시합니다. 전체 연구의 완료와 구분합니다.

## 7. 정기 운영과 인수인계

주간 점검을 운영한다면 [현황판](../templates/02_연구현황판.md)에서 지난 산출물, 현재 장애, 다음 검토물과 날짜만 확인합니다. 월별 또는 주요 단계 전환 시 RQ·기여·설계·공식 마감의 변경을 다시 대조합니다. 주간·월간은 조정 가능한 운영 예시입니다.

담당 교체 시 [인수인계서](../templates/05_인수인계.md)에 최신 원고, 열린 의견, 실제 받은 결정, 공식 마감, 접근권한 인계 상태를 남깁니다. 비밀번호나 인증키를 인수인계 문서에 적지 않습니다.
