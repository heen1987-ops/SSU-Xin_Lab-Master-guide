# 문서관리·출처·개정 원칙

문서가 늘어나도 독자가 어느 문서를 먼저 읽고 어디를 수정해야 하는지 알 수 있도록 대표 문서와 상세 자료의 역할을 정합니다. 기준을 복사해 늘리기보다 대표 문서로 연결합니다.

## 1. 문서의 역할

| 위치 | 역할 | 수정할 때 |
|---|---|---|
| 루트 README | 목적·대상·시작 경로 | 상세 규정·운영 절차는 옮겨 적지 않고 연결 |
| handbook | 학술총무 운영, 석박사 상담, 방법별 검토, 스킬 사용 | 연구실에서 조정 가능한 운영안임을 표시 |
| templates | 복사해 쓸 빈 서식 | 작성법·상태값을 유지하고 실데이터를 넣지 않음 |
| 19·20·21·22번 | 연구 흐름·문제정의·실증설계·원문근거의 대표 안내 | 해당 주제의 기준 변경을 이곳에 반영 |
| 방법별 트랙·단계별 지침 | 구체적 방법과 단계의 상세 안내 | 공통 내용을 반복하지 않고 연결·예외를 설명 |
| 학사·서식 문서 | 적용 대상별 과거 확인 기록과 공식 출처 | 조항·적용 대상·확인일·미확인을 함께 갱신 |
| docs / html | 웹 배포본 / 같은 내용의 로컬 열람본 | 생성 파일과 수동 편집 파일을 구분해 동기화 |

핸드북과 서식의 웹 열람본은 Markdown에서 생성합니다. 해당 HTML을 직접 고치지 않고 원문과 생성 스크립트를 수정합니다. 기존 상세 웹페이지는 수동 관리 대상이며 Markdown 변경의 영향을 함께 확인합니다.

## 2. 출처의 성격과 확인 상태

| 성격 | 사용할 수 있는 범위 | 반드시 남길 것 |
|---|---|---|
| 공식 규정·학기 공지 | 적용 대상의 절차·요건 | 기관·제목·URL·적용 학기·조항·확인일 |
| 학술 원문 | 해당 연구가 보고한 주장과 조건 | 문헌 ID·판본·읽은 위치·실제 대조 범위 |
| 강의자료·논문 사례 | 개념 설명·작성 방식의 참고 | 원출처·원래 확인일·사례라는 성격 |
| 연구실 운영안 | 검토 흐름·서식·내부 일정 | 제안/채택 상태와 적용 범위 |
| 교육용 예시·AI 초안 | 작성 연습·질문·수정 후보 | 가상/미검증 표시와 확인할 근거 |

한 출처가 모든 판단에서 우선하는 것은 아닙니다. 학사 자격은 공식 규정, 연구 주장은 실제 원문·자료, 내부 운영은 연구실 합의에서 확인합니다. 강의자료나 사례에 있는 분량·장수·표본 수를 공식 의무로 승격하지 않습니다.

## 3. 2026-10-15 공식 출처 확인 범위

| 출처 | 이번에 확인한 범위 | 남겨 둔 확인 과제 |
|---|---|---|
| [IT정책경영학과 자격시험](https://itpm.ssu.ac.kr/page/exam.php) | 네 과정의 학점·등록학기 요건과 연 2회 안내가 기존 요건표와 일치 | 개인의 학적·응시 가능 회차와 당해 학기 세부 공지 |
| [2026-2 일반대학원 학위논문 공지](https://grad.ssu.ac.kr/정보광장/공지사항/?slug=12720) | 공지 본문과 일정표, 첨부 서식 목록의 존재 | 첨부 HWP·DOCM·PDF 본문 전체, 이후 정정 공지, 개인별 적용 |
| [학칙시행세칙 연결 주소](https://rule.ssu.ac.kr/lmxsrv/law/lawFullContent.do?SEQ=103&SEQ_HISTORY=2485) | 규정 본문 접근 가능 여부 | 최신 시행 판본 여부와 각 조항의 개별 재검증 |

이 확인으로 기존 문서의 모든 규정·서식을 최신 검증 상태로 바꾸지 않습니다. 특히 고정된 `SEQ_HISTORY` 주소는 판본을 가리킬 수 있으므로 현재 시행본인지 따로 확인합니다. [규정 확인표](../templates/06_규정확인.md)에 확인 범위를 기록한 뒤 해당 문장만 갱신합니다.

## 4. 변경과 재검토

원문 문장, 근거 위치, 변경 이유, 영향을 받는 문서와 웹페이지를 묶어 기록합니다. 검토자가 실제로 확인한 파일 판본과 범위를 남깁니다. 원고나 근거가 바뀌면 관련 주장을 다시 확인하며 날짜·해시만 갱신해 검토한 것으로 처리하지 않습니다.

기존 공유 주소를 바꿀 때는 이전 주소에서 새 위치로 이동할 방법을 남깁니다. 원자료와 사람 주석은 검토 편의를 위해 덮어쓰지 않습니다. 원문 삭제·재배포는 보유 권한과 사용자 요청을 별도로 확인합니다.

## 5. 공개 자료와 내부 운영 기록

이 공개 저장소에는 일반 안내·빈 서식·표시된 가상 예시를 둡니다. 학생 원고·참여자 자료·서명·연락처·실제 지도 의견은 연구실의 제한된 공간에서 관리합니다. 인수인계에는 접근권한의 담당과 확인 상태를 남기되 인증정보를 기록하지 않습니다.

연구 ID를 익명화해도 내용·기관·주제 조합으로 식별될 수 있으므로, 공개 교육 사례는 공유 가능 범위를 확인한 뒤 작성합니다. 빈 서식을 공개했다고 실제 작성본의 공개까지 허용되는 것은 아닙니다.

## 6. 개정 후 확인

1. 요청한 대상과 산출물이 문서 첫 화면에서 드러나는가.
2. 같은 주제의 대표 문서와 상세 링크가 일관적인가.
3. 운영 제안·규정·사례·실측·AI 의견을 구분했는가.
4. 석사·박사, 연구방법, 산출형식을 혼동하지 않았는가.
5. 링크·목차·웹 생성본·다운로드가 현재 원문과 일치하는가.
6. 남은 미확인 사항과 다음 갱신 담당이 기록되어 있는가.

검사 명령과 웹 생성 절차는 [관리자 안내](../scripts/README.md)에 있습니다. 파일·링크 검사 통과는 학술적 타당성·원문 검수·공식 승인 확인을 대신하지 않습니다.
