# SSU 논문 스킬로 검토·수정하기

통합 호출명은 **`$ssu-paper`**, 표시 이름은 **SSU_논문**입니다. 사용 중인 환경에서 설치본을 먼저 확인하고 현재 단계에 필요한 기능을 사용합니다. 이 저장소는 사용 안내와 서식을 제공하며 스킬 본체나 비공개 강의 원문을 배포하지 않습니다.

## 1. 작업 전에 정할 것

| 항목 | 적을 내용 |
|---|---|
| 연구와 산출물 | 연구 주제, 과정, 학위논문/학술지/미정 |
| 방법 | engineering / empirical / mixed / undecided와 선택 이유 |
| 현재 작업 | 문헌·문제·설계·분석·집필·심사 중 이번 범위 |
| 입력 판본 | 파일명·판본·검토할 장·절·쪽, 근거 파일의 실제 위치 |
| 근거 상태 | 실제 읽은 문헌, 확보 자료, 실행 결과, 미확인·미실행 |
| 제약 | 제공 자료만 사용/공개 검색 허용, 수정할 파일 범위, 자료 처리 조건 |
| 원하는 결과 | 수정 문안, 주장–근거표, 지적·응답표, 다음 확인 항목 등 |

학생마다 [검토 요청서](../templates/01_검토요청.md)를 먼저 만들면 같은 설명을 반복할 필요가 줄어듭니다. 여러 연구를 함께 검토해도 연구 ID와 입력 폴더·판본을 구분합니다. 다른 학생이나 Ph01·Ph02 등의 자료·결과를 이름이 비슷하다는 이유로 합치지 않습니다.

## 2. 기본 요청문

```text
$ssu-paper
목적: 신랩 내부 논문 검토와 수정 보조
연구 ID / 과정: [입력]
산출형식: [학위논문 / 학술지 / 미정]
방법: [실증 / 공학·실험 / 혼합 / 미정]
현재 단계와 이번 검토 범위: [입력]
입력 원고·판본·근거 파일: [실제 파일]
실제 실행·원문 독해 범위와 미확인 사항: [입력]
자료 사용과 수정 범위: [입력]

먼저 주장과 근거의 연결을 읽고 핵심 결함을 설명해 줘.
그다음 문제·기여, 방법, 근거·논증 관점에서 빠진 항목을 점검해 줘.
지적마다 위치·근거·영향·수정안·재확인 조건을 제시해 줘.
허용한 범위의 실제 수정본과 지적 대응표를 만들어 줘.
자료가 없으면 수치·인용·검수·승인을 만들지 말고 다음 확인을 남겨 줘.
이번에 실제 읽고 실행한 범위와 한계를 마지막에 정리해 줘.
```

## 3. 상황별로 덧붙일 요청

### 주제와 기여를 좁힐 때

```text
제공한 문헌에서 저자가 직접 보고한 한계와 나의 해석을 구분해 줘.
공백 후보–RQ–기여–비교·대안–검증–반증 조건을 연결해 줘.
가장 가까운 선행연구와 실제로 대조한 범위에서만 신규성을 설명해 줘.
아직 확보하지 못한 문헌·자료가 무엇인지와 범위를 줄일 대안도 적어 줘.
```

### 석사·박사 원고의 범위를 상담할 때

```text
학위명으로 장수·가설 수·표본 수를 정하지 말고 지도교수와 합의한 범위를 우선해 줘.
각 핵심 기여가 기존 연구와 어떻게 다르고 무엇으로 입증되는지 확인해 줘.
복수 연구라면 연구별 단위·증거·실행상태와 전체 기여의 연결을 구분해 줘.
내용 추가가 필요한 이유와 주장을 줄여 해결할 수 있는 부분을 구분해 줘.
```

### 분석·실험 결과를 검토할 때

```text
원계획과 실제 수행의 차이, 독립 단위, 제외·실패·결측, 비교 조건을 확인해 줘.
결과표의 수치를 실행 기록과 대조하고 단위·분모·집계·불확실성을 점검해 줘.
새 분석이 필요하면 이유·입력·조건부터 제안해 줘.
실제 데이터나 실행 도구가 없으면 결과 분석은 미실행으로 표시해 줘.
```

### 심사 의견에 대응할 때

```text
제공한 실제 의견과 AI가 예상한 질문을 분리해 줘.
의견 원문–수용/설명/보류–수정 위치–근거–재검토 상태를 연결해 줘.
한 에이전트의 관점 검토는 자기점검으로 표시하고 독립 심사라고 부르지 마.
미해결 핵심 문제를 총점이나 한계 문단 추가만으로 닫지 마.
```

## 4. 결과를 받을 때 확인할 것

- **지침을 읽음:** 스킬과 모듈을 불러온 상태. 연구·분석을 수행했다는 뜻이 아니다.
- **파일을 검사함:** 경로·형식·링크·해시를 확인한 상태. 내용의 진실성을 보증하지 않는다.
- **실제 연구 작업:** 검색·독해·코드 실행·수정 등 수행한 작업과 입력·출력이 확인된다.
- **내용 재검토:** 수정 판본에서 해당 주장을 다시 대조한 범위가 기록된다.
- **사람 확인:** 실제 전달받은 의견·확인 기록이 있을 때만 적는다.

스킬은 분석계획과 코드 작성에 도움을 줄 수 있지만, 제공되지 않은 모델 실험이나 통계분석을 실행했다고 기록하면 안 됩니다. 원문 일부 독해를 전체 검수로 확대하지 않습니다. AI 의견은 연구자의 판단·지도·공식 심사를 보조합니다.

## 5. 설치본과 판본 관리

이번 문서 개편은 2026-10-15 설치된 통합 2.3.0의 진입점과 학위·집필·심사 관련 본문을 읽어 적용했습니다. 설치 경로는 PC마다 다르므로 다른 PC에서 같은 경로가 있다고 가정하지 않습니다. 배포·갱신은 [스킬 저장소](https://github.com/heen1987-ops/Xin_Lab_Thesis_Skill-Codex-claude-)의 실제 브랜치·배포 manifest와 설치본을 대조하세요. 저장소 기본 브랜치가 통합 배포본이라는 보장은 없습니다.

CLI를 쓰는 환경에서는 아래와 같이 실제 절대경로를 지정할 수 있습니다. 명령 예시의 `SKILL_ROOT`와 `OUTPUT`은 자리표시자입니다.

```text
python SKILL_ROOT/scripts/paper_router.py load --document-kind thesis --method undecided --stage writing --out OUTPUT/skill-load.json
python SKILL_ROOT/scripts/paper_router.py check-load --input OUTPUT/skill-load.json
```

`load`는 지침 로딩, `check-load`는 해당 판본의 재대조입니다. 실행 영수증을 만들었다면 별도로 `check-run`을 확인합니다. 도구가 없는 환경에서는 실제 본문을 직접 읽고 가능한 문서 작업을 수행한 범위와 실행하지 못한 부분을 남깁니다. 학생의 결과물은 스킬 설치 폴더 밖에 저장합니다.
