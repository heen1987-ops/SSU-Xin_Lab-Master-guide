# 재현성·파일·버전관리 지침

목표: 학생 본인과 다른 연구자가 최종 표·그림·결론이 어떤 원자료, 코드, 조건과 결정에서 만들어졌는지 다시 추적하고 재실행할 수 있게 한다.

## 용어를 먼저 선언
- 재현성(reproducibility): 같은 입력자료·코드·계산절차·분석조건으로 일관된 결과를 얻는 것
- 반복검증(replicability): 같은 과학적 질문을 새로운 자료로 다시 연구해 불확실성을 고려한 일관된 결과를 얻는 것
- 일반화 가능성(generalizability): 다른 모집단·상황·시점에도 결과가 적용되는 정도
- 분야별 용어 관행이 다를 수 있으므로 논문에서 채택한 정의를 먼저 밝힌다.
- 같은 코드 오류도 그대로 반복될 수 있으므로 재현 성공 자체가 결과의 정확성을 보증하지는 않는다.

## 권장 폴더 구조
00_admin       일정·승인·회의·심사기록
01_protocol    연구계획·가설·실험설계·변경이력
02_literature  원문·서지정보·문헌비교표
03_raw         변경하지 않는 원자료·원로그
04_clean       정제자료·데이터사전·제외기록
05_code        수집·정제·분석·시각화 코드
06_results     자동 생성된 표·그림·모형 출력
07_manuscript  장별 원고·통합 원고·제출본
08_defense     발표자료·질문·심사의견 반영표
09_archive     최종 제출 증빙·공개 가능한 연구패키지

## 파일명 규칙
YYYYMMDD_프로젝트_내용_v01_작성자.ext

예시:
20270312_thesis_hypothesis-map_v03_KIM.docx
20270402_thesis_clean-data_v02_KIM.csv
20270618_thesis_full-manuscript_v07_KIM.docx

- final, final2, 진짜최종 같은 파일명은 사용하지 않는다.
- 버전이 올라간 이유를 변경기록에 한 줄로 남긴다.
- 제출본은 날짜·제출처·상태가 보이도록 별도 보관한다.

## 데이터 파이프라인
원자료 → 검증 → 정제 → 파생변수/전처리 → 분석·실험 → 표·그림 → 원고

- 각 단계는 이전 단계 파일을 덮어쓰지 않는다.
- 수작업 수정은 피하고 불가피하면 셀·값·이유·날짜를 로그로 남긴다.
- 데이터사전에 변수명, 정의, 단위, 코딩, 결측, 출처, 사용제한을 기록한다.
- 분석표와 그림은 가능하면 코드에서 자동 생성한다.

## 실증논문 재현정보
- 원표본과 최종표본의 연결, 제외·결측 처리, 변수 변환
- 패키지·명령·모형식·통제변수·가중치·표준오차 방식
- 분석 순서, 다중검정, 매개·조절·강건성 사양

## 실험논문 재현정보
- 데이터 버전·분할·전처리, 누수 방지 절차
- 하드웨어, OS, 언어, 라이브러리와 버전
- Random Seed, 반복횟수, Hyperparameter 탐색범위·선택기준
- 제안방법과 핵심 Baseline을 실행하는 정확한 명령
- Baseline 구현출처, 튜닝예산, 중단조건, 실행당·전체 실행시간과 CPU/GPU·메모리
- 오차막대의 변동원과 산출법, 데이터·코드·모델의 버전·원출처·라이선스

## TOP 2025 공개상태표
항목 | 상태 | 공개 URL·식별자 | 제한·불가 사유 | 합법적 접근조건 | 확인일

항목 7개:
- 연구등록
- 프로토콜
- 분석계획
- 연구재료
- 분석코드
- 데이터
- 보고 투명성(적용 보고지침·누락 설명)

상태는 미실시 / 보유·비공개 / 제한접근 / 공개 URL·식별자 / 공개 불가로 구분한다. 민감정보·계약·저작권으로 공개할 수 없다면 항목을 삭제하지 않고 사유와 검증 가능한 접근조건을 남긴다.

## README 필수 항목
- 연구목적과 RQ
- 폴더·파일 설명
- 핵심 결과를 재생성하는 정확한 실행 명령
- 환경 잠금 파일과 OS·언어·패키지 버전
- 원자료 확보조건, 데이터사전, 라이선스와 접근 제한
- 원자료 → 정제자료 → 표·그림의 전체 실행순서
- 입력·중간·출력 파일의 버전과 안정적 식별자
- 예상 실행시간·계산자원·출력 위치
- 빈 결과 폴더에서 전체 재실행한 검증일
- 알려진 제한·오류·공개 불가 항목
- 문의·책임자·버전 날짜

## 백업 원칙
- 작업본 하나만 남기지 않는다.
- 장치 장애와 계정 장애를 분리할 수 있는 두 위치 이상에 보관한다.
- 민감자료는 승인된 저장소와 암호화·접근권한 기준을 따른다.
- 백업이 존재하는지만 보지 말고 정기적으로 복원 가능한지 확인한다.

## 결과 동결 절차
1. 최종 분석대상·코드·환경을 잠근다.
2. 모든 표·그림을 빈 폴더에서 다시 생성한다.
3. 원고의 수치와 생성 결과를 대조한다.
4. 버전 태그와 변경이력을 남긴다.
5. 제출본과 재현패키지를 별도 보관한다.

## 완료기준
- 원자료를 훼손하지 않고 최종 결과까지 경로가 연결됨
- 다른 장치에서 README 순서로 핵심 결과를 재생성할 수 있음
- 원고·표·그림·코드가 같은 데이터 버전을 사용함
- 민감·계약자료를 제외한 공개범위를 설명할 수 있음
- 본인의 지도교수가 최종 결과 버전과 보관범위를 확인함
