# 실험논문 지침

목표: 처치·시스템·알고리즘의 효과와 성능 차이를 공정한 비교, 반복검증, 재현 가능한 절차로 설명한다.

실제 집필·확정: 제3장 연구설계 → 제4장 연구결과 → 제5장 결론 → 제2장 관련 연구 → 제1장 서론

## 권장 흐름
문제·기술 Gap → 제안방법/처치 → 비교조건 → 데이터 → 평가 Metric → 실험절차 → 주요 비교 → 통계검정 → Ablation·강건성 → 실패사례

## 제2장
- 문제영역과 대표 기술·알고리즘·실험 패러다임
- 기존 접근법의 가정·강점·실패조건 비교
- 제안방법이 해결하는 정확한 기술적 Gap
- Baseline 선정의 학술적·실무적 근거
- 평가 Metric이 실제 목표와 연결되는 이유
- 데이터셋·실험조건·선행성능의 비교 가능성

## 제3장
- 시스템·모형·처치의 구조와 작동원리
- 데이터 출처·기간·수집조건·라이선스·전처리
- Train/Validation/Test 분리와 Data Leakage 방지
- 처치군·통제군, 무작위화·맹검·조작점검 해당 여부
- Baseline과 동일한 데이터·예산·튜닝·하드웨어 조건
- 하드웨어·OS·언어·라이브러리·버전·Random Seed와 정확한 실행명령
- Hyperparameter 탐색범위와 선택기준
- 반복횟수·통계검정·중단기준·실패기준과 오차막대 산출법

## 설계와 보고표준 구분
- 사람 대상 무작위배정 시험: CONSORT 2025를 적용하고 참여자 흐름·등록·프로토콜·위해를 보고한다.
- 사람 대상 비무작위 실험: JARS–Quant와 해당 분야 지침을 우선하며 CONSORT 적용을 주장하지 않는다.
- 알고리즘·시스템·모델 벤치마크: 목표 학회 지침과 재현성·아티팩트 체크리스트를 적용한다.
- CONSORT는 일반 계산실험의 품질인증 수단이 아니다.

## 제4장 제시 순서
실험환경 → 데이터·Baseline → 주요 성능 → 반복 평균·편차/CI → 비교검정 → Ablation → Sensitivity → Robustness → 효율·자원 → 실패사례

## 공정 비교
- 제안방법과 Baseline에 동일한 정보·데이터·평가예산을 제공
- 유리한 Metric만 선택하지 않고 사전 정의한 주 Metric을 우선 보고
- 최고값 하나보다 반복 평균, 분산, 신뢰구간과 효과크기를 보고
- 오차막대가 포착하는 변동원(Seed·분할·초기화·표본추출)과 SD·SE·CI 중 무엇인지 명시
- 실행당 CPU/GPU·메모리·시간과 전체 연구 계산량, 튜닝 비용·추론비용을 비교
- 데이터·코드·모델의 정확한 버전·원출처·라이선스와 공개 불가 사유·검증 대체경로를 기록
- 실제 적용 경로가 있으면 개인정보·공정성·보안·오용 위험과 완화책을 보고

## 핵심 위험
- 테스트셋을 개발·튜닝에 사용한 데이터 누수
- Baseline의 부실한 구현 또는 불공정한 튜닝
- 하나의 Seed·분할·데이터셋 결과만 보고
- 통계적으로 유의하지만 실무적으로 미미한 차이를 과장
- 실패사례와 불리한 조건을 제외
- 코드·환경·데이터 버전이 남지 않아 결과 재현 불가

## 완료기준
- 동일 조건에서 비교가 가능함
- 데이터·환경·절차·Seed·Hyperparameter가 기록됨
- 반복·Ablation·Sensitivity·Robustness 결과가 있음
- 실패조건과 적용 경계를 설명함
- 다른 연구자가 핵심 결과를 재현할 수 있음
- 본인의 지도교수가 추가실험 범위와 전체 원고를 확인함
