# 기각·실패·데이터 부족·일정 복구 지침

원칙: 예상과 다른 결과는 숨기거나 가설을 사후 변경할 이유가 아니다. 사실·원인후보·확인 가능한 조치·남은 일정을 분리하고 본인의 지도교수와 연구범위를 재결정한다.

## 문제 분류
- 이론 문제: Gap·가설·메커니즘이 결과를 설명하지 못함
- 측정 문제: 척도·센서·레이블·조작이 개념을 제대로 반영하지 못함
- 데이터 문제: 표본 부족, 편향, 결측, 누수, 접근권한, 품질 저하
- 분석 문제: 가정 위반, 코드 오류, 모형 부적합, 다중검정
- 실험 문제: 처치 실패, Baseline 불공정, 환경 차이, 재현 실패
- 일정 문제: 승인·수집·장비·검토 지연으로 임계경로가 밀림
- 행정 문제: 공식 신청·윤리·서류·심사 마감 위험

## 공통 복구 순서
1. 현재 파일과 원자료를 덮어쓰지 않고 문제 버전을 보존한다.
2. 관찰된 사실과 추측을 분리한다.
3. 전체 연구를 다시 하지 않고 원인을 구분할 최소 진단을 정한다.
4. 필수 RQ·결과와 선택적 추가분석을 나눈다.
5. 조치별 시간·성공기준·중단기준을 계산한다.
6. 선택지 A/B와 일정 영향을 지도교수에게 제시한다.
7. 결정 후 프로토콜·제3장·분석로그·일정을 함께 수정한다.

## 가설 기각·무효과
- 코딩·척도방향·분석대상·가정과 검정력이 먼저 정확한지 확인한다.
- 효과크기와 CI로 "효과가 없음"과 "정밀하게 알 수 없음"을 구분한다.
- 상반 선행연구와 표본·맥락·측정·시점 차이를 비교한다.
- 가설을 결과에 맞춰 바꾸지 않고 기각 결과의 이론적 의미를 논의한다.
- 새 가설·탐색분석은 사후·탐색적 분석으로 명시한다.

## 표본·데이터 부족
- 최소 분석 가능 표본과 현재 표본의 차이를 계산한다.
- 추가수집 가능기간·비용·윤리·동일조건 유지 가능성을 점검한다.
- 무리한 표본확대 대신 RQ·집단비교·모형 복잡도를 줄이는 선택지를 만든다.
- 편의표본·결측·선택편향과 일반화 제한을 명시한다.
- 사용할 수 없는 데이터는 대체자료보다 연구질문 변경이 필요한지 검토한다.

## 실험 실패·성능 미달
- 데이터·코드·환경·Seed·Baseline을 최소 예제로 재현한다.
- 예상 성능과 실제 성능의 차이를 구성요소·조건별로 분해한다.
- 실패를 숨기지 않고 오류유형과 작동하지 않는 조건을 결과로 전환한다.
- 추가 튜닝은 예산·범위·종료조건을 먼저 정한다.
- 개선폭이 작으면 성능우월성 대신 효율·안정성·오류감소 등 실제 기여를 재평가한다.

## 일정 지연 시 보호할 순서
1. 지도교수의 전체 원고 검토시간
2. 필수 연구질문에 답하는 주 분석·실험
3. 윤리·공식 신청·심사·제출 마감
4. 표·그림·수치 정합성 검수
5. 선택적 추가분석·장식적 내용

- 뒤 단계의 검토시간을 줄여 일정을 맞추지 않는다.
- 먼저 선택적 RQ, 세부 집단, 추가 Metric, 반복되지 않은 확장실험의 범위를 조정한다.
- 연구범위 축소·방법변경·공개발표 진행 여부는 본인의 지도교수가 결정한다.

## 금지사항
- 유의한 결과가 나올 때까지 분석·표본·제외기준을 반복 변경
- 실패한 실행·기각가설·데이터 제외 기록 삭제
- 문제를 숨긴 채 다음 원고 단계로 이동
- 지도교수 확인 없이 연구질문·방법·결론을 크게 변경
- 마감 직전에 처음으로 일정 위험 보고

## 완료기준
- 문제의 사실·원인·조치·결정·버전이 기록됨
- 핵심 RQ를 보호하면서 선택적 범위를 합리적으로 줄임
- 사후분석·프로토콜 변경을 투명하게 표시함
- 결과의 주장강도와 일정이 현실적으로 재설정됨
- 본인의 지도교수가 복구안과 변경된 공개발표·제출 경로를 확인함
