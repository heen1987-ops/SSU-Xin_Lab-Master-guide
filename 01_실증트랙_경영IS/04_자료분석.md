# 자료 분석

## 1. 데이터를 얼마나 갖고 있는지에 따라 할 일이 다르다

| 보유 상태 | 지금 할 일 |
|---|---|
| 원자료와 실행 도구가 있음 | 실제 분석을 실행하고, 입력 버전·코드/설정·출력 경로·실제 결과를 연결해 기록한다 |
| 통계표/출력만 있음 | 수치 간 일관성과 보고 내용을 검토한다. 원자료 재분석·가정검사를 했다고 쓰지 않는다 |
| 일부 추정치만 있음 | 지금 쓸 수 있는 문장과, 앞으로 더 필요한 출력 목록을 나눠 정리한다. 없는 CI·SE·p를 채워 넣지 않는다 |
| 데이터가 아예 없음 | 분석계획·빈 결과표·결과 문장 템플릿만 만든다 |

**원칙: 실제 데이터·분석 출력이 없으면 표본 수, 계수, p, CI, 신뢰도 같은 수치를 절대 지어내지 않습니다.** 설명을 위한 가상 수치는 반드시 "가상 예시"라고 표시합니다.

## 2. 분석 방법은 소프트웨어 경험이 아니라 연구 질문으로 고른다

| 연구가 요구하는 것 | 검토할 방법 | 남겨야 할 선택 근거 |
|---|---|---|
| 관측변수 간 관계·설명 | 회귀 등 자료형에 맞는 모형 | 종속변수 분포, 독립성, 교란변수, 추정량 |
| 잠재구성개념과 공분산 구조 | CFA·CB-SEM | 식별, 척도, 추정 방법, 자료 적합성 |
| 구성개념/합성변수와 예측 중심 목표 | PLS-SEM | 측정 관점, 예측 평가, 필요한 표본·가정 |
| 실험·패널·군집 자료 | 해당 설계에 맞는 분석 | 배정, 시간, 군집·반복측정 구조 |

"SPSS/AMOS를 쓸 줄 안다"는 이유만으로 방법을 정하지 않습니다. Python/R 등 다른 도구를 써도 되지만, 실제로 동등한 분석을 수행했는지 확인하고 사용 도구·버전을 정확히 밝힙니다. "데이터가 작고 비정규분포라서 PLS를 쓴다"는 설명만으로 모든 방법론적 문제가 해결되지는 않습니다.

## 3. 측정모형 → 구조모형 순서로 확인

1. 데이터 정의·코딩·응답 범위·결측/중복/이상값·최종 분석표본을 확인한다.
2. 각 척도의 분포와 문항 간 관계를 본다.
3. 내용·수렴·판별타당성의 증거와 측정모형을 점검한다(모형 식별 실패, 비정상 추정값을 숨기지 않는다).
4. 측정의 한계를 반영해 구조 경로, 설명력·효과크기·불확실성을 평가한다.
5. 계획된 보조·민감도 분석과 사후 탐색적 분석을 분리해서 보고한다.

## 4. 가설검정표

| H ID·대상 효과 | 분석 N·모형/출력 | 추정치(표준화 여부 포함) | SE·CI | 검정통계량·p | 판정(지지/미지지/판정 불가) |
|---|---|---|---|---|---|

- 통계적 유의성은 효과 크기나 실무적 중요성의 척도가 아닙니다. **비유의 = 효과 없음**이 아닙니다.
- p가 `.000`으로 나와도 실제로는 `p < .001` 등으로 반올림된 값입니다. 정확한 자릿수를 모르면 값을 역산해 만들지 않습니다.

### 매개효과

X→M, M→Y 각각의 유의성이나 X→Y 직접효과의 비유의만으로 "완전매개"를 확정하지 않습니다. 간접효과의 신뢰구간(부트스트랩 등)과 시간 순서·교란 가능성을 함께 보고합니다.

### 조절·집단 비교

한 집단은 p<.05, 다른 집단은 p>.05라는 이유만으로 "집단 간 차이가 있다"고 결론짓지 않습니다. 상호작용항 검정이나 측정불변성 확인 등 정식 절차를 거칩니다. 데이터를 보고 나서 집단을 나눴다면 탐색적 분석이라고 밝힙니다.
